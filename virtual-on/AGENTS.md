# Project facts

- Standalone HTML, CSS, and JavaScript; no package installation or build step.
- Two entry points: `index.html` + `style.css` preserve the original widescreen presentation; `square.html` + `square.css` provide a separate 1:1 composition designed at 1080×1080. Both use `scene.js`. Do not remove or replace the original when changing the square version.
- Square rendering is opt-in through `data-layout="square"` on the canvas. The square has no visible top panel, side dashboard, chapter navigation, or scrubber. Hidden/inert runtime bindings allow the shared controller to run without duplicating animation logic. Keyboard Space still toggles playback; the existing seek API remains available for capture.
- Preserve the entire `.intro` block in the square version, including eyebrow, heading, caption, and both reference lines. Its text must match the widescreen version verbatim at every chapter until the user explicitly asks for replacement copy. The square moves this block inward over the artwork with a readability gradient; future Workflow Data Fabric copy belongs here, but no protocol wording or mappings have been added.
- Rendering uses Canvas 2D with explicit perspective projection, polygon sorting, and surface-attached details. No WebGL, 3D libraries, or AI-generated imagery.
- All seven protagonist chest marks use the approved transparent `servicenow-mark-lineart.png`, attached to chest surfaces with perspective-mapped triangles. Virtuaroid 1 has a widened central chest panel; the former central triangles/reactor spots are replaced by the mark. The unknown adversary remains unbranded. Robot green accents and the PNG use exactly `#63DF4E` (`brandGreen` in `scene.js`); retain the other armor colors. The logo has a monochrome rendering for MONO mode.
